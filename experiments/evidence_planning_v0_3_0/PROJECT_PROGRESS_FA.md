# ثبت محلی مرحلهٔ برنامه‌ریزی شواهد

۲۰نوامبر۲۰۲۶ — کاربر پیاده‌سازی مسیر جدید را تأیید کرد: تمرکز بر حفظ وابستگی، کفایت شواهد و تصمیم بازیابی؛۴۰ سؤال قبلی فقط توسعه؛ نخست آزمایش کنترل‌شدهٔ ارزش ساختار؛ سپس مقایسهٔ کامل و ارزیابی روی سؤال‌های جدید.

مبنای حفظ‌شده: v3.2.4-max4، بسته با SHA256 برابر ad77a0d34992910d089f13fa30efee27040132bc3a93e6c8d868a10ef5a0a62b. تاریخچهٔ خوانده‌شده در commit d3c5a1522389db5eb07cfb8a3418500e423371cc است. کد هستهٔ مبنا بایت‌به‌بایت ثابت و آرشیو اصلی نیز نگهداری شده است.

ساخته‌شده: بستهٔ مستقل planning_lab، دادهٔ۲۰۰وضعیتی بر۴۰سؤال، جداسازی برچسب خصوصی، دو حالت با تنها تفاوتِ ساختار صریح، قرارداد خروجی تصمیم، backend اختیاری Qwen/CUDA، ثبت هزینه و resume، مشاهده‌گر ساختاری، گزارش و ZIP، برگهٔ داوری مستقل و ارزیابی با مخرج معلوم، کنترل هم‌پوشانی مجموعهٔ تازه.

دامنهٔ کنترل‌شده: یک فراخوانی تصمیم برای هر حالت/وضعیت، بدون اجرای query پیشنهادی.۳۷سؤال معتبر و۳نامعتبر در مبنا حفظ شدند. ادعای حفظ معنای همهٔ درخت‌ها وجود ندارد. حذف شاهد مرجع، برچسب ناکافی‌بودن خودکار ایجاد نمی‌کند.

بررسی نرم‌افزار: آزمون‌ها در verification/offline_tests.txt و نتیجهٔ کنترل هویت در verification/preflight.json ثبت می‌شوند. این بررسی‌ها مدل ساختگی دارند یا بدون مدل‌اند؛ نتیجهٔ زبانی Qwen نیستند. شاخص‌های ساختگی آزمون‌ها در results اصلی قرار نمی‌گیرند.

اجرای واقعی: انجام نشده. محیط ساخت فاقد torch/transformers بود؛ مسیر GPU و Windows هنوز به اجرا در محیط کاربر نیاز دارد. هزینهٔ واقعی برنامهٔ جدید و دقت تصمیم‌ها موجود نیست؛ عددی برای آن‌ها ساخته نشده است.

کارهای باقی‌مانده: اجرای مرحلهٔ کنترل‌شده، داوری مستقل، تحلیل جفت‌شده، تصمیم دربارهٔ کنترل‌گر حلقه‌بسته، اتصال سه مسیر کامل با بودجهٔ مشترک، تشکیل و ثبت مجموعهٔ دیده‌نشده و ارزیابی نهایی. ثبت نامزد heldout فقط هم‌پوشانی شناسه/متن را بررسی می‌کند و جای آزمون تعمیم را نمی‌گیرد.

تحویل فقط در همین گفتگو؛ هیچ commit/push یا انتشار GitHub انجام نشده است. دستور تاریخی ثبت آنلاین با درخواست فعلی تحویل محلی جایگزین شده است.

۲۱نوامبر۲۰۲۶ — بسته‌بندی نسخهٔ۰٫۱ برای تحویل در چت ادامه یافت.۴۲ آزمون نرم‌افزار آفلاین پاس شده و کنترل ورودی مشترک برای۱۸۵ جفت معتبر موفق بود. فایل راهنمای شروع سریع اضافه شد. وضعیت اجرای واقعی همچنان انجام‌نشده است.

۲۱نوامبر۲۰۲۶ — کاربر درخواست۱۵ سؤال جدید برای ارزیابی نهایی داد. نسخهٔ۰٫۲ مجموعهٔ ثابت۱۵تایی را از mirror عمومی HotpotQA انتخاب کرد:۸ bridge و۷ comparison؛ انتخاب بر پایهٔ هش شناسه و بدون نتیجهٔ مدل.۸۹ شناسه و۵۴۱ هش متن در سوابق موجود بررسی شدند؛ هم‌پوشانی انتخاب نهایی صفر است. منشأ mirror، commit و هش در manifest ثبت شده‌اند؛ میزبان اصلی از شبکهٔ محیط قابل دسترس نبود.

مسیر نهایی اضافه شد: قفل کد/تنظیمات/داده، تولید درخت با تابع اصلی max4 و حداکثر۲ تلاش ساختاری، ثابت‌کردن درخت برای هر دو حالت، حفظ تمام۱۵ سؤال حتی هنگام شکست، ثبت هزینهٔ تولید جدا از تصمیم‌ها، ادامهٔ بدون فراخوانی تکراری و خروجی ZIP کامل. مسیر عمومی run نقش heldout را نمی‌پذیرد؛ اجرای نهایی از run-final15 انجام می‌شود. بازسازی توسعه ثبت۱۵ سؤال را حفظ می‌کند.

هیچ مدل زبانی روی۱۵ سؤال منتخب اجرا نشده است. آزمون‌های چرخهٔ نهایی فقط از سؤال‌های مصنوعی استفاده می‌کنند. دامنهٔ این نسخه همچنان تصمیم‌گیری یک‌مرحله‌ای است؛ اجرای واقعی query و مقایسهٔ سه مسیر کامل RAG انجام نشده‌اند. این ثبت محلی است و به GitHub فرستاده نشده است.

۲۱ نوامبر ۲۰۲۶ — بررسی عمیق نسخهٔ۰٫۲ نشان داد اجراگر فقط structured/flat و یک تصمیم روی شاهد ثابت دارد؛ retrieve اجرا نمی‌شود و مشاهده‌گر ساختاری تصمیم را تغییر نمی‌دهد. آزمون مستقل با پاسخ مصنوعی این محدودیت‌ها را بازتولید کرد. ۵۷ آزمون نسخهٔ۰٫۲ پاس شدند؛ این موفقیت نرم‌افزار به معنی تکمیل پایپ‌لاین سه‌روش نبود.

کاربر صریحاً درخواست کرد هم بررسی انجام شود و هم چهار مورد در کد نهایی تکمیل شوند. نسخهٔ۰٫۳ در پوشهٔ مستقل ساخته شد. فایل‌های جدید rag_runtime، rag_retrieval، rag_support، rag_methods، rag_runner، rag_evaluation، rag_cli و run_rag.py اجرای مشترک Standard اصلی، max4 با طرح ثابت و کنترل‌گر فعال Operadic را اضافه کردند. کد/پرامپت/درخت‌های مبنا تغییر نکرده‌اند؛ آزمایش دوحالتهٔ قبلی حفظ شده است.

تصمیم retrieve اکنون جست‌وجوی واقعی را اجرا و شواهد تازه را وارد ارزیابی می‌کند. مصرف پاسخ پیش‌نیاز و منابع آن ثبت می‌شود؛ گره وابسته مسدود می‌ماند تا پیش‌نیاز پشتیبانی شود. بررسی پشتیبانی با فراخوانی جداگانهٔ همان مدل، کنترل نقل‌قول واقعی و بررسی هدف اصلی همراه است؛ تأیید مدل حقیقت مستقل نیست. کنترل توقف فعال است و پایان بودجه از توقف موفق جدا ثبت می‌شود. شواهد تازه پاسخ‌های cache و وابستگان را برای بررسی دوباره نامعتبر می‌کنند.

تنظیمات اولیهٔ مشترک: Qwen/revision ثابت، hybrid BGE/BM25 مبنا،۲۴ فراخوانی/۴۸۰۰۰ توکن/۲ بازیابی/۳ سند تازه برای هر سؤال و روش. هزینهٔ طرح در بودجهٔ هر بازوی درختی منظور می‌شود ولی در مصرف واقعی کل، تولید مشترک یک بار حساب می‌شود. تنظیمات هنوز نتیجهٔ تنظیم تجربی نیستند. معیارهای پاسخ و پوشش بازیابی روی همهٔ سؤال‌ها، شامل شکست‌ها، محاسبه می‌شوند؛ معیارهای معنایی به داوری مستقل نیاز دارند.

همان۱۵ سؤال نهایی حفظ شده‌اند. مسیر جدید۴۵ رکورد اصلی می‌سازد؛ شکست طرح حذف یا جایگزین نمی‌شود. قفل استفادهٔ۱۵ سؤال بین پروتکل قدیمی و جدید مشترک است. چرخهٔ کامل۱۵سؤالی/۴۵اجرایی فقط با سؤال‌های مصنوعی بررسی شد.۸۸ آزمون آفلاین پاس شدند؛ آزمون واقعی Qwen/CUDA، encoder واقعی BGE، نتایج مدل روی دادهٔ پژوهش و داوری مستقل همچنان انجام نشده‌اند. هیچ فراخوانی روی۱۵ سؤال واقعی منتخب انجام نشد. گزارش بررسی در docs/AUDIT_AND_CHANGES_FA.md و راهنمای اجرا در docs/RAG_V03_FA.md است. این ثبت محلی است؛ GitHub تغییر نکرد.
