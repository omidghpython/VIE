# راهنمای داوری مستقل تصمیم و شاهد

فایل برگه‌ها نام حالت آزمایش را نشان نمی‌دهد. برای هر برگه فقط فیلد review را تکمیل کنید؛ نام و کد حالت را از مجری نخواهید. اگر مطمئن نیستید، final را false نگه دارید و علت را بنویسید. صرف برچسب supported مدل را شاهد صحت نگیرید.

## ارزیابی وضعیت شواهد

`state_sufficient`: آیا متن شواهدِ همین برگه برای پاسخ به سؤال اصلی کافی است؟ دانستهٔ بیرونی یا صرف دانستن پاسخ مرجع کافی نیست. یک شاهد جایگزین معتبر قابل پذیرش است. در استنتاج مقایسه‌ای، مقدمات لازم و اتصال مقدارها به موجودیت‌ها باید روشن باشند. این برچسب برای دو خروجیِ یک وضعیتِ یکسان باید یکسان باشد؛ اختلاف‌ها پیش از محاسبه داوری شوند.

## ارزیابی تصمیم

- `decision_acceptable`: آیا stop/retrieve/abstain با وضعیت شواهد و محدودیت روش سازگار است؟ توقف با پاسخ بی‌پشتوانه قابل قبول نیست. برای پاسخ منفی، نبود اشاره به یک واقعیت لزوماً شاهد نفی آن نیست.
- `target_acceptable`: برای retrieve، آیا نیاز انتخاب‌شده یکی از نیازهای واقعی و قابل اقدام است؟ چند هدف درست می‌تواند وجود داشته باشد. درخواست ویژگیِ موجودیت هنوز شناسایی‌نشده ممکن است نیازمند حل پیش‌نیاز باشد.
- `query_acceptable`: آیا query نیاز انتخاب‌شده را دقیق و با جهت، موجودیت، ویژگی و قیود درست دنبال می‌کند؟ این معیار کیفیت پیشنهاد است، نه موفقیت بازیابیِ اجراشده.
- `binding_correct`: آیا پاسخ و شاهد به موجودیت و ویژگی درست متصل‌اند؟ اگر برگه برای قضاوت کافی نیست، null مجاز است و مخرج آن جدا گزارش می‌شود.

## ارجاع‌ها

تمام ادعاهای واقع‌نما در پاسخ‌های زیرسؤال و پاسخ نهایی را بررسی کنید؛ دلیل کوتاهِ تصمیم اگر ادعای واقع‌نما دارد نیز در دامنه باشد. برای مقایسه و استنتاج، مجموعهٔ ارجاع‌ها باید مقدمات لازم را پوشش دهد. وجود صرف نام موجودیت یا موضوعِ مشابه، پشتیبانی از رابطه/ویژگی نیست.

- `cited_claims`: تعداد ادعاهای اتمیِ دارای ارجاع.
- `supported_cited_claims`: تعداد همان ادعاها که ارجاع‌ها واقعاً پشتیبانی‌شان می‌کنند.
- `required_claims`: تعداد ادعاهای اتمیِ نیازمند شاهد، چه ارجاع داشته باشند چه نداشته باشند.
- `supported_cited_required_claims`: تعداد ادعاهای نیازمند شاهد که ارجاع پشتیبان دارند.

اگر خروجی هیچ ادعای قابل ارزیابی ندارد، مخرج صفر است و امتیاز null می‌شود، نه۱. اگر بررسی ارجاع انجام نشده، هر دو عضو جفت را null بگذارید؛ این فقدان بررسی از امتیاز پایین جدا است.

پس از پایان، reviewer_id و comment را بنویسید و final را true کنید. برای retrieve، تصمیم درستِ query و target باید جدا مشخص شوند. داوری با همان مدلِ تصمیم‌گیر، «داور مستقل» محسوب نمی‌شود. در صورت استفاده از داور مدل دیگر نیز بخشی از موارد باید انسانی بررسی شود و هویت داور ثبت شود.

این ارزیابی با bootstrap در سطح سؤال تحلیل می‌شود؛ چند وضعیت یک سؤال نمونه‌های مستقل نیستند. خروجی برنامه درصدهای دارای مخرج را می‌دهد و موارد بررسی‌نشده را مشخص نگه می‌دارد.
