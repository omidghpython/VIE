نصب مجدد محیط HotpotQA نسخهٔ۰٫۳ — بستهٔ بازیابی۱
تاریخ تهیه:۲۱ نوامبر۲۰۲۶، تهران

فایل اصلی نصب: restore_environment_windows.bat

این بسته برای همان محیط Windows و GPU انویدیا قبلی پروژه آماده شده است. ZIP کامل، کد و دادهٔ نسخهٔ۰٫۳ را بدون تغییر همراه نصاب دارد؛ مدل‌های سنگین هنگام نصب دانلود می‌شوند.

مراحل:
۱. ZIP را در پوشه‌ای تازه روی دیسکی با فضای کافی باز کنید؛ اجرای فایل از داخل خود ZIP درست نیست.
۲. وارد پوشهٔ hotpotqa_evidence_planning_v3 شوید.
۳. restore_environment_windows.bat را اجرا کنید و تا پیام READY منتظر بمانید.
۴. پس از پایان موفق، برای شروع کار توسعه start_development_windows.bat را اجرا کنید. این فایل محیط نصب‌شده را فعال می‌کند و سپس اجراگر توسعهٔ نسخهٔ۰٫۳ را فراخوانی می‌کند.
۵. برای فرمان‌های دیگر، open_hotpotqa_terminal.bat ترمینالی با همین محیط باز می‌کند. دستورهای run.py و run_rag.py را در آن ترمینال اجرا کنید.

پیش‌نیازهای سیستمی:
Python 64-bit نسخهٔ۳٫۱۰تا۳٫۱۳ و درایور NVIDIA باید نصب باشند. نسخهٔ۳٫۱۳ با راه‌اندازی قبلی پروژه هم‌خوان است. اگر خود Python پاک شده، Python 3.13 x64 را از python.org نصب کنید. اگر nvidia-smi کار نمی‌کند، درایور/اتصال GPU را در ماشین ابری برگردانید. نصاب Python یا درایور سیستم‌عامل را خودکار نصب نمی‌کند؛ نصب CUDA Toolkit جداگانه برای این مسیرِ wheelهای آماده لازم نیست.

نصاب چه می‌کند؟
- یک محیط مستقل با نام .venv_hotpotqa می‌سازد؛ محیط یا فایل‌های قبلی را حذف نمی‌کند.
- PyTorch نسخهٔ2.11.0+cu128 را از مخزن رسمی CUDA در pytorch.org نصب می‌کند.
- requirements-live.txt و requirements-test.txt را با نسخه‌های اصلی ثبت‌شدهٔ قبلی نصب می‌کند: Transformers 4.57.6، Accelerate 1.15.0 و BitsAndBytes 0.50.2.
- pip check، دسترسی واقعی CUDA و یک عملیات کوچک و مصنوعی NF4 را بررسی می‌کند؛ در صورت خطا متوقف می‌شود.
- Qwen2.5-7B-Instruct و BGE small en v1.5 را با revision دقیق مبنا در cache معمول Hugging Face دانلود می‌کند.
- وجود shardهای Qwen، tokenizer/config و بارگذاری آفلاین BGE را کنترل می‌کند. مدل Qwen برای تولید پاسخ اجرا نمی‌شود.
- هویت فایل‌های پروژه را قبل و بعد از نصب بررسی می‌کند. تنظیم allow_model_download و هیچ فایل پایپ‌لاین تغییر نمی‌کند؛ برنامه بعداً از cache آماده استفاده می‌کند.
- وضعیت هر تلاش را در recovery_logs نگه می‌دارد.

این کار ممکن است به‌دلیل دانلود وزن‌های چندین‌گیگابایتی و کتابخانه‌های CUDA زمان ببرد. برای محیط، وزن‌ها و فایل‌های موقت فضای کافی روی دیسک cache و پوشهٔ پروژه در نظر بگیرید. دانلودهای کامل موجود دوباره دریافت نمی‌شوند؛ در صورت قطع اینترنت، اجرای مجدد همان نصاب از cache استفاده می‌کند.

اگر خطا دیدید:
متن خطا و فایل JSON همان تلاش در recovery_logs را نگه دارید. تا پیام READY، نصب کامل اعلام نشده است. خطای CUDA با نصب کتابخانهٔ Python به‌تنهایی همیشه برطرف نمی‌شود؛ درایور و نمایش GPU باید درست باشند. پوشهٔ ناقص .venv_hotpotqa خودکار حذف نمی‌شود.

چرا نصاب قدیمی کافی نبود؟
install_windows.bat قدیمی عمداً torch را نصب نمی‌کرد تا نسخهٔ CUDA از قبل سالم را حفظ کند. نسخهٔ۰٫۳ نیز برای استفاده از همان محیط ساخته شده بود. این بستهٔ بازیابی، نصب PyTorch از صفر و آماده‌کردن مدل‌ها را اضافه می‌کند.

بررسی انجام‌شده هنگام ساخت:
وجود نسخه‌های اصلی در PyPI و wheel رسمی Windows مربوط به torch2.11.0+cu128 بررسی شد. منطق نصاب، ترتیب نصب، توقف هنگام خطا، حفظ فایل‌ها و نرفتن به ارزیابی با آزمون‌های نرم‌افزار بررسی می‌شوند. اجرای واقعی نصاب روی Windows/GPU و دانلود وزن‌ها در محیط ساخت انجام نشده است؛ بررسی سخت‌افزار واقعی هنگام اجرای فایل روی ماشین شما انجام می‌شود.

نصاب هیچ‌یک از۴۰ سؤال توسعه یا۱۵ سؤال نهایی را اجرا نمی‌کند و ثبت استفادهٔ مجموعهٔ نهایی را پاک نمی‌کند. کد و manifest اصلی۰٫۳ تغییر نکرده‌اند. کنترل پژوهشی OC-ABLATION-01 همچنان باز است و قبل از ارزیابی نهایی باید دوباره مطرح شود.

این بسته کتابخانه‌ها و مدل‌ها را دوباره آماده می‌کند؛ نتیجه‌ها، لاگ‌ها یا سابقهٔ استفادهٔ حذف‌شده را بازیابی نمی‌کند. اگر قبلاً سؤال‌های نهایی را اجرا کرده‌اید، سابقهٔ آن باید از نسخهٔ پشتیبان حفظ شود؛ استخراج دوبارهٔ ZIP آن سؤال‌ها را «دیده‌نشده» نمی‌کند.
